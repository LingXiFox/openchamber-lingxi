# OpenChamber LingXiFox 1.0.1

LingXiFox 1.0.1 moves the desktop product to the OpenChamber 1.21.0 upstream base while retaining LingXi's independent product version and identity.

## Source migration

- Upstream commit: `ad7fd356339ccc5c9af5af1a6786662572d53ed0`
- DEV integration source: `6afd22ca6ff203980735e870737b3871b8093e60`
- Legacy release preparation: `a83fd4cfbd51d6bacb21a134777afcf31ffbe079`
- Canonical DEV source anchor: `65492ce5d5e89aaf4475f309b0ca24bf4cb0300d`

The canonical anchor differs from the DEV integration source only by setting the Electron product version to `1.0.1`. Its build-relevant paths match the legacy release preparation commit. Run:

```bash
bun run release:lingxi:parity a83fd4cfbd51d6bacb21a134777afcf31ffbe079 65492ce5d
```

## Candidate evidence

The machine record contains a verified local macOS arm64 candidate: DMG, ZIP, blockmaps, updater manifest, and checksums. It uses Apple Development signing and is not notarized. Those files do not contain a source commit attestation, so their exact binary build commit remains unverified.

At the time this candidate record was written, Windows x64 and Linux x64 were waiting for GitHub Actions native dry-runs. A formal tag run rebuilds all targets, verifies both artifact upload/download round trips, and publishes the newly assembled bytes. Windows installers remain unsigned until a separate signing design is approved.

Exact macOS artifact metadata and target status are in [the machine record](../../.lingxi/releases/1.0.1.yml).
